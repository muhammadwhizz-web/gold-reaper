## Question 5 — does SL-first over-penalize?

Re-run with TP checked before SL inside each bar: **net unchanged to the cent**
(-970.12, same 48 trades). With SL at 1.2×ATR, intra-bar SL/TP conflicts are
rare on H1 gold. **The pessimistic fill assumption is NOT the problem.**

## Question 8 — does ML improve with a longer window?

20 YEARS of daily bars, expanding 5-fold, same XGBoost family:
fold AUCs **0.541 / 0.482 / 0.559 / 0.531 → mean 0.528 → FAIL (< 0.56 gate)**.

Longer history does not rescue tabular ML on gold direction. The meta-model
stays a soft vote; the hard gate stays disarmed. This is now confirmed twice
(hourly: 0.50, daily-20y: 0.528).

## The fixes we shipped (walk-forward validated, worst-fold rule)

From `research/tune_v3.py` — a config is promoted only if its **worst fold**
improves and full-period net does not degrade:

1. **Session tightening** — hunt only 12:00–13:59 UTC (was 12:00–15:59).
   Independent evidence: hour buckets (Q2) and the tuner agree.
2. **Target-math retune** — TP 2.0R (was 2.67R). With 1% risk and a 2.67R
   target the math demanded a >38% win rate the entries couldn't deliver;
   2.0R neighbors (1.8/2.0/2.2R) all hold the worst-fold gain — no knife-edge.
3. **Mean-reversion vol ceiling** — meanrev may only fire when the entry bar's
   ATR-rank < 0.40 (Q7: low-vol tape is where meanrev survives).

Rejected by the data: time-stop (no effect under tightened gates), weekday
filter (noise), vol band on all modules (kills the sample), sl_atr changes
(worse worst-fold).

## Read this part twice

- **8–11 trades is not a sample, it's an anecdote.** A PF of 2.57 on 8 trades
  is indistinguishable from luck. We are publishing it because the walk-forward
  structure is honest (expanding-window ML, no same-bar re-entry, costs both
  sides) — not because it proves an edge.
- The v2.2 config lost -970. The v3 config survives the same window near
  breakeven-to-slightly-positive with 60% less drawdown. That is **damage
  reduction**, the only honest claim available at this sample size.
- The arbitration is live: `docs/TRACK_RECORD.md` is an append-only paper
  ledger. If v3 is a statistical accident, the paper ledger will say so in
  public. If it has a real edge, the same ledger will accumulate the evidence.
- Nothing here is a promise of profit. See `docs/RISK.md`.
